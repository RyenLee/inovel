# 风险评估与缓解策略

> 项目：inovel v0.1.0 | 生成日期：2026-05-05

---

## 总览

对数据迁移全程进行系统性风险识别，每个风险项包含：触发条件、影响范围、严重等级、缓解措施和应急预案。

---

## 风险清单

### R1：文件夹重命名冲突

| 属性 | 内容 |
|------|------|
| **风险描述** | 目标路径已存在同名文件夹，导致 `fs::rename` 失败。生成的项目 ID 可能与已有文件夹名冲突 |
| **触发条件** | 随机生成的 `PXXXXX` ID 与已有文件夹名重合（概率极低，约 1/33^5 = 1/39M） |
| **影响范围** | 单个项目迁移失败 |
| **严重等级** | 🟢 低 |
| **缓解措施** | 重命名前检查目标路径是否存在。若存在则重新生成 ID，最多重试 3 次 |
| **应急预案** | 若冲突持续，跳过该项目并记录日志，由管理员手动处理 |
| **验收标准** | 迁移后目标目录无一覆盖已有文件 |

### R2：文件名非法字符

| 属性 | 内容 |
|------|------|
| **风险描述** | 旧项目以书名命名文件夹，书名的 Windows 非法字符（`/ \ : * ? " < > \|`）导致文件夹创建/重命名失败 |
| **触发条件** | 已有项目使用了包含非法字符的书名作为文件夹名（这些文件夹**本就不该存在**，但为了安全仍需检查） |
| **影响范围** | `fs::rename` 调用失败 |
| **严重等级** | 🟢 低（旧项目目录已存在即说明其路径本身合法） |
| **缓解措施** | 迁移前检查所有待迁移项目的旧路径，使用 `Path::exists()` 确认可访问 |
| **应急预案** | 若路径非法导致无法重命名，记录错误并跳过，保留原项目数据 |
| **验收标准** | 迁移日志记录所有异常路径，无数据丢失 |

### R3：Git 仓库引用断裂

| 属性 | 内容 |
|------|------|
| **风险描述** | `fs::rename` 重命名文件夹后，`.git` 目录内的配置文件可能包含绝对路径引用，需要处理 |
| **触发条件** | 项目使用了 Git 仓库，且 `.git/config` 包含绝对路径 |
| **影响范围** | 重命名后 Git 操作（commit, log, status）可能失败 |
| **严重等级** | 🟡 中 |
| **缓解措施** | 重命名后调用 `git2::Repository::open` 验证仓库可打开；然后执行 `git status` 确认工作正常 |
| **应急预案** | 若 Git 仓库损坏，记录日志但**不阻断迁移**（Git 数据可通过 `.git/objects` 恢复） |
| **验收标准** | 重命名后 Git 仓库可正常读取，`git log` 能返回历史记录 |

### R4：文件权限不足

| 属性 | 内容 |
|------|------|
| **风险描述** | 项目目录下的文件被其他进程锁定或为只读，导致 `fs::rename` 失败 |
| **触发条件** | 编辑器或其他程序正在打开项目中的文件 |
| **影响范围** | 单个项目迁移失败，原文件夹可能处于不一致状态 |
| **严重等级** | 🟡 中 |
| **缓解措施** | 迁移前提示用户关闭所有编辑器中的项目文件；`fs::rename` 前检查目录可写性 |
| **应急预案** | 重命名失败时回滚事务（不会改变原文件），记录错误并提示用户关闭文件后重试 |
| **验收标准** | 所有项目文件夹迁移成功，无残留中间状态 |

### R5：磁盘空间不足

| 属性 | 内容 |
|------|------|
| **风险描述** | VACUUM INTO 生成数据库备份时，磁盘空间不足 |
| **触发条件** | 目标盘剩余空间 < 数据库文件大小 |
| **影响范围** | 无法创建备份，迁移中止 |
| **严重等级** | 🟡 中 |
| **缓解措施** | 迁移前检查可用空间；VACUUM INTO 到与数据库不同盘（数据盘） |
| **应急预案** | 跳过自动备份，提示用户手动备份后重试 |
| **验收标准** | 备份文件创建成功，校验其 SHA256 值与原库一致 |

### R6：迁移过程意外中断

| 属性 | 内容 |
|------|------|
| **风险描述** | 迁移执行过程中应用崩溃、系统关机或断电 |
| **触发条件** | 硬件故障、系统更新重启、Tauri 应用进程被 kill |
| **影响范围** | 可能造成部分项目已迁移、部分未迁移的不一致状态 |
| **严重等级** | 🔴 高 |
| **缓解措施** | 采用逐项目事务：每个项目作为一个独立事务。失败时只回滚当前项目；已完成的迁移不受影响 |
| **应急预案** | 再次执行迁移命令（幂等设计：会跳过已迁移项目） |
| **验收标准** | 迁移中断可安全重入，重执行后状态与一次执行完成一致 |

### R7：UNIQUE 约束冲突

| 属性 | 内容 |
|------|------|
| **风险描述** | `project_id` 列有 UNIQUE 约束，生成 ID 时碰撞概率虽低但存在 |
| **触发条件** | 随机 ID 生成与已有 project_id 重复 |
| **影响范围** | SQLite UNIQUE 约束违反，INSERT/UPDATE 失败 |
| **严重等级** | 🟢 低 |
| **缓解措施** | 生成时使用 `check_project_id_exists` 检查；最多重试 100 次（project.rs:36-46 已实现） |
| **应急预案** | 若 100 次仍碰撞，记录错误并跳过该项目 |
| **验收标准** | 迁移后 `SELECT project_id, COUNT(*) FROM projects GROUP BY project_id HAVING COUNT(*) > 1` 返回 0 行 |

### R8：封面文件路径失效

| 属性 | 内容 |
|------|------|
| **风险描述** | project.json 中 cover_path 存储的是相对路径，文件夹重命名后该路径仍正确（因为相对路径不变），但需确认 |
| **触发条件** | 封面路径存储在 project.json 中且为相对路径 |
| **影响范围** | 封面图片无法加载 |
| **严重等级** | 🟢 低 |
| **缓解措施** | project.json 中的 cover_path 本身是相对路径（如 `covers/三体_cover.jpg`），不依赖文件夹名。迁移后验证该路径的绝对路径解析正确 |
| **应急预案** | 若 cover_path 因某种原因使用了绝对路径，修正后重新读取 |
| **验收标准** | 迁移后 `open_project` 返回的 cover_path 可正确访问图片 |

### R9：并发执行风险

| 属性 | 内容 |
|------|------|
| **风险描述** | 迁移过程中用户同时打开了其他项目页面或触发了其他 Tauri 命令 |
| **触发条件** | 用户在迁移过程中切换到其他功能 |
| **影响范围** | 竞争条件导致数据不一致 |
| **严重等级** | 🟡 中 |
| **缓解措施** | 前端迁移过程中禁用导航；后端使用 `conn.lock()` 或 SQLite WAL 模式确保串行访问 |
| **应急预案** | 添加前端状态锁，迁移执行时阻止其他 DB 操作 |
| **验收标准** | 迁移期间所有非迁移 DB 操作返回友好提示，不引发数据冲突 |
